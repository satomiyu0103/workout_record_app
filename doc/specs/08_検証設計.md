## 受け入れ基準（AC：Acceptance Criteria＝完了とみなす条件）

### 機能要件 FR-EXR-001 — 種目プリセット（カテゴリ EXR＝種目マスタ）

- [ ] 初回起動時、次の 8 種目が選択可能である: ベンチプレス、バーベルスクワット、デッドリフト、ラットプルダウン、レッグプレス、懸垂（重量＝体重＋重り）、腕立て伏せ、ショルダープレス
- [ ] プリセット種目は `menu_master` に存在し、再起動後も残る

### 機能要件 FR-EXR-002 — 種目カスタム登録（カテゴリ EXR＝種目マスタ）

- [ ] 新規種目名を入力して登録できる
- [ ] 登録した種目が記録画面の種目一覧に表示される
- [ ] 空文字の種目名は登録できず、エラーメッセージが表示される
- [ ] 既存種目と同名の登録は拒否される（デシジョンテーブル DT-EXR-002 のルール R4）

### 機能要件 FR-REC-001 — トレ記録登録（カテゴリ REC＝トレーニング記録）

- [ ] 日付・種目・重量・回数を入力して保存すると SQLite に 1 セット分のレコードが追加される
- [ ] アプリ再起動後も保存した記録が参照できる
- [ ] 機内モード（オフライン）でも登録できる
- [ ] 重量 ≤ 0、小数第 3 位以上、または回数 < 1 のとき保存できず、エラーが表示される
- [ ] トレ日に **未来日** を指定したとき保存できず、エラーが表示される
- [ ] 複数項目が同時に不正のとき、**最初の 1 件のエラー** のみ表示する（優先: 種目 → 重量 → 回数。デシジョンテーブル DT-REC-001 ルール R8）
- [ ] 保存操作でタイマーが自動起動しない

### 機能要件 FR-REC-002 — トレ記録参照（カテゴリ REC＝トレーニング記録）

- [ ] 選択した日付・種目の過去セットが一覧表示される
- [ ] 表示順は **登録の新しい順**（`created_at` 降順）である

### 機能要件 FR-REC-003 — トレ記録削除（カテゴリ REC＝トレーニング記録）

- [ ] 一覧の **ゴミ箱アイコン** → 確認で削除を選ぶと DB から消える（デシジョンテーブル DT-REC-003 のルール R1）
- [ ] 確認でキャンセルするとレコードは残る（デシジョンテーブル DT-REC-003 のルール R2）
- [ ] 既に DB に無い ID の削除は **成功扱い** とし、一覧を再読込する。トースト・エラーは出さない（デシジョンテーブル DT-REC-003 のルール R3・冪等削除・利用者承認 2026-08-18）
- [ ] その日・その種目の最後の 1 セットを削除すると、空状態表示になる（デシジョンテーブル DT-REC-003 のルール R4）

### 機能要件 FR-HIS-001 — 履歴一覧（カテゴリ HIS＝履歴・カレンダー）

- [ ] **設定タブ** →「トレーニング履歴」から種目を選ぶと、その種目の全期間のセット履歴が **日付の降順** でリスト表示される

### 機能要件 FR-HIS-002 — カレンダー表示（カテゴリ HIS＝履歴・カレンダー）

- [ ] 当月カレンダーに記録のある日が **記録マーク** で視覚的に区別できる（重量数値は出さない）
- [ ] 記録マークに 1RM や最大重量の数値は **表示されない**
- [ ] 日付をダブルタップすると、入力画面が該当日付で開く

### 機能要件 FR-SYS-002 — タイマー任意起動（カテゴリ SYS＝システム機能）

- [ ] 主要画面右上のタイマーアイコンからタイマー画面を開ける
- [ ] 初回は 90 秒でカウントダウンが開始できる（クイックスタート）
- [ ] ±30 秒ボタンで残り時間を調整できる
- [ ] 前回設定した秒数が **同一セッション内** の次回クイックスタートに反映される（プロセス終了後は 90 秒）
- [ ] カウント中に記録を保存してもタイマーは **停止しない**
- [ ] 0 秒到達時は **画面表示とバイブ** のみ（**音は出さない**）
- [ ] バックグラウンドから復帰したとき、**終了予定時刻** に基づき残り秒が正しく表示される

### 機能要件 FR-SYS-003 — ダークモード既定 UI（カテゴリ SYS＝システム機能）

- [ ] 初回起動時、画面背景が暗色・文字が明色である（[DESIGN.md](../../DESIGN.md) のトークンに準拠）
- [ ] 入力・カレンダー・設定の各画面でダークテーマが一貫している

### MVP 否定の受け入れ基準（スコープ外の非表示）

- [ ] 入力画面に「次回の推奨重量」「次回の推奨回数」「目標セット」等の文言・数値が **表示されない**
- [ ] 入力画面・履歴・カレンダーに 1RM の算出値が **表示されない**（Phase 2 まで）

### 非機能要件 NFR-SEC-001 / NFR-OPS-001

- [ ] ネットワーク未接続で記録・参照・タイマーが動作する
- [ ] ログイン画面・アカウント登録が存在しない

### 非機能要件 NFR-PERF-001

- [ ] 実機で cold start から入力画面が操作可能になるまで 1 秒以内（3 回計測の中央値）

### Android 配布・個人運用（受け入れ基準 AC-DPL / AC-OPS）

> 詳細・**デシジョンテーブル（DT）**・**状態遷移表（ST）**: [08b_検証設計_Android配布運用.md](08b_検証設計_Android配布運用.md)  
> 手順: [flutter-android.md](../reference/setup/flutter-android.md)

- [ ] release APK（Android インストール用ファイル）をビルドし、API 26 以上の実機にインストールできる（デシジョンテーブル DT-DPL-001 ルール R2, DT-DPL-002）
- [ ] サイドロード後、初回起動でクラッシュしない（デシジョンテーブル DT-DPL-002 ルール R3）
- [ ] 機内モードで記録・履歴・タイマーが動作する（デシジョンテーブル DT-OPS-001。非機能要件 NFR-OPS-001 と整合）
- [ ] 同一署名 APK の上書き更新後も記録が参照できる（デシジョンテーブル DT-DPL-004 ルール R1, DT-OPS-002 ルール R1）
