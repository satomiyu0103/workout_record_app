# 広告・収益化メモ（実装未定）

最終更新: 2026-08-18

> **位置づけ**: 将来の検討用メモ。正式な FR / AC ではない。実装するか未定・急ぎではない。

---

## 目的

| 項目 | 内容 |
|---|---|
| 収益目標 | **累計 ¥3,000 程度**で開発コスト（Cursor 利用料など）の回収を目安にする |
| その後 | お小遣い感覚。月次の固定回収を前提にしない |
| UX | トレ中フローを壊さない。最小限の広告配置 |

---

## 収益モデル（案）

| 方式 | 内容 |
|---|---|
| 無料版 | 閲覧系画面にバナー広告（AdMob アダプティブバナー想定） |
| 買い切り | 設定から「広告を非表示」— 機能ロックではなく応援課金。価格帯 ¥480〜980 を候補 |
| やらない | 起動時・保存直後のインタースティシャル（全画面広告）、動画広告 |

バナー単体では利用者が少ない段階では月数百円になりやすい。**累計 ¥3,000** は、買い切り数件 + バナーの積み上げで現実的なライン。

## 広告を置く場所（最小構成）

### 置く

| 画面 | 位置 | 備考 |
|---|---|---|
| **レポートタブ** | コンテンツ最下部・底部タブ直上 | 主収益枠。MVP 時はプレースホルダ文言の下 |
| **設定画面** | 「アプリについて」の下 | 副収益枠。課金導線の近く |

合計 **常時 1〜2 枠**。トレ中は **0 枠**。

### 置かない

| 画面・タイミング | 理由 |
|---|---|
| 入力タブ（重量・回数・保存） | インターバル中の主導線。[DESIGN.md](../../../DESIGN.md) の大きなタップ領域と競合 |
| タイマーオーバーレイ | カウントダウン中の妨害 |
| 入力内の当日セット一覧 | 記録の主導線 |
| カレンダータブ | ダブルタップで入力へ戻る。タブバーとバナーの干渉 |
| 全画面共通バナー（3タブ常時） | トレ中も広告が見える |
| アプリ起動直後 | [NFR-PERF-001](02_要件定義.md)（起動 1 秒以内）と矛盾 |

## オフライン・失敗時

地下ジムなど通信不通時（[NFR-OPS-001](02_要件定義.md)）:

- 広告枠は **非表示**（記録・タイマーは従来どおり動作）
- ロード失敗・オフライン時に灰色の「広告」プレースホルダやエラー UI は出さない
- 広告 SDK の初期化は **初回画面描画後** に遅延（起動速度を守る）

## 実装する場合の技術メモ（参考）

| 項目 | 候補 |
|---|---|
| 広告 | `google_mobile_ads`、ウィジェットは `AdBannerSlot` 等でラップ |
| 課金 | `in_app_purchase`、非消耗型（買い切り） |
| 配置 | `core/ads/` に `AdService`（プレミアム判定・オンライン判定・表示可否） |
| ストア | プライバシーポリシー・データ収集申告が別途必要（AdMob は端末情報を送る） |

## 導入タイミング（案・急がない）

| 段階 | 内容 |
|---|---|
| MVP 完了後 | レポート 1 枠のみから検討 |
| 利用者が少しついたら | 設定 2 枠目 + 買い切り課金 |
| Phase 3 グラフ追加後 | 広告位置は変えない（レイアウト安定） |

MVP と同時公開は、初回レビューで「広告がうるさい」と言われるリスクがある。実装するなら **レポート 1 枠のみ** からが無難。
