## 受け入れ基準（AC：Acceptance Criteria＝完了とみなす条件）— 配布・運用

### 受け入れ基準 AC-DPL（配布：Deploy）

- [ ] `flutter doctor` で Android toolchain が利用可能である（デシジョンテーブル DT-DPL-001 ルール R1）
- [ ] `flutter build apk --release` が成功し、`app-release.apk` が生成される（デシジョンテーブル DT-DPL-001 ルール R2）
- [ ] API 26 以上の実機に APK をインストールし、ホーム画面から起動できる（デシジョンテーブル DT-DPL-002 ルール R1 または R2）
- [ ] 初回起動でクラッシュせず、入力画面まで到達できる（デシジョンテーブル DT-DPL-002 ルール R3）
- [ ] 同一署名の新 APK で上書きインストールでき、既存記録が参照できる（デシジョンテーブル DT-DPL-004 ルール R1）

### 受け入れ基準 AC-OPS（運用：Operations）

- [ ] 機内モードで記録登録・履歴参照・タイマーが動作する（デシジョンテーブル DT-OPS-001 ルール R1〜R3。非機能要件 NFR-OPS-001 と整合）
- [ ] cold start から入力画面が操作可能になるまで 1 秒以内（3 回計測の中央値。非機能要件 NFR-PERF-001）
- [ ] アプリ更新（APK 上書き）後も SQLite の記録が残る（デシジョンテーブル DT-OPS-002 ルール R1）
- [ ] ネットワーク復帰後もログイン画面等が出ない（非機能要件 NFR-SEC-001 / オフライン設計）

## デシジョンテーブル（DT）

### デシジョンテーブル DT-DPL-001 — 配布：開発 PC のビルド環境

| ルール（R） | `flutter doctor` | Android SDK | 実行コマンド | 期待結果 |
| --- | --- | --- | --- | --- |
| R1 | Android 欄に問題なし | インストール済 | `flutter doctor` | ビルド可能と判断できる |
| R2 | 問題なし | インストール済 | `flutter build apk --release` | 成功。`app-release.apk` が出力される |
| R3 | Android 欄に ✗ あり | — | `flutter build apk --release` | 失敗。先に環境修復（※1） |
| R4 | 問題なし | 未インストール | `flutter build apk --release` | 失敗。SDK 導入後に再実行 |

**補足（DT-DPL-001）**

- ※1（R3）: `flutter doctor` の指摘に従いライセンス同意・`ANDROID_HOME` 設定等を実施。[flutter-android.md](../reference/setup/flutter-android.md) 参照。

---

### デシジョンテーブル DT-DPL-002 — 配布：実機への初回インストール

| ルール | 端末 OS | インストール方法 | 提供元不明の許可 | 期待結果 |
| --- | --- | --- | --- | --- |
| R1 | API 26 以上 | USB + `adb install` | — | インストール成功。ランチャーにアイコン |
| R2 | API 26 以上 | APK ファイル転送（※1） | 許可済 | インストール成功 |
| R3 | API 26 以上 | R1 または R2 後 | — | 起動成功。クラッシュしない |
| R4 | API 25 以下 | 任意 | — | 非対応。インストール不可または動作保証外 |
| R5 | API 26 以上 | APK 転送 | 未許可 | OS がインストールをブロック。設定で許可後に再試行 |

**補足（DT-DPL-002）**

- ※1（R2）: ドライブ・メール・USB ストレージ等で `app-release.apk` を端末へ渡す。Play ストアは不要。

---

### デシジョンテーブル DT-DPL-003 — 配布：開発中の USB デバッグ実行

| ルール | USB 接続 | USB デバッグ | PC で端末認識 | 実行コマンド | 期待結果 |
| --- | --- | --- | --- | --- | --- |
| R1 | あり | ON | `flutter devices` に表示 | `flutter run` | ビルド・インストール・起動成功 |
| R2 | あり | ON | 未表示 | `flutter run` | 失敗。ドライバ・ケーブル・許可ダイアログを確認 |
| R3 | あり | OFF | — | `flutter run` | 失敗。開発者向けオプションで ON |
| R4 | なし | — | — | `flutter run` | 実機なし。エミュレータまたは接続後に再実行 |
| R5 | あり | ON | 表示 | ホットリロード（`r`） | UI 変更が実機に反映 |

---

### デシジョンテーブル DT-DPL-004 — 配布：APK 更新（上書きインストール）

| ルール | 既存アプリ | 新 APK の署名 | 利用者の操作 | 期待結果 |
| --- | --- | --- | --- | --- |
| R1 | インストール済 | 同一（※1） | 新 APK をインストール | 上書き成功。データ保持（デシジョンテーブル DT-OPS-002 と整合） |
| R2 | インストール済 | 異なる | 新 APK をインストール | 失敗または別アプリ扱い。アンインストールが必要な場合あり |
| R3 | 未インストール | 任意 | 初回インストール | 新規インストール成功 |

**補足（DT-DPL-004）**

- ※1（R1）: Flutter の既定 release ビルドは同一 keystore を使い続ける限り署名が一致する。keystore を作り直した場合は R2 相当になり得る。

---

### デシジョンテーブル DT-OPS-001 — 運用：ジム想定のオフライン日常利用

| ルール | ネットワーク | 利用者の操作 | 事前に記録あり | 期待結果 |
| --- | --- | --- | --- | --- |
| R1 | 機内モード | 重量・回数を保存 | いいえ | 保存成功（機能要件 FR-REC-001 / 非機能要件 NFR-OPS-001） |
| R2 | 機内モード | 履歴一覧を開く | はい | 過去記録が表示される |
| R3 | 機内モード | タイマーを起動 | — | カウントダウンが動作する |
| R4 | 機内モード | アプリ再起動 | はい | 記録が残り、ログイン画面は出ない |

---

### デシジョンテーブル DT-OPS-002 — 運用：更新後のデータ保持

| ルール | 更新方法 | DB マイグレーション | 期待結果 |
| --- | --- | --- | --- |
| R1 | 同一署名 APK で上書き | スキーマ変更なし | 全記録が参照できる |
| R2 | 同一署名 APK で上書き | スキーマ変更あり（※1） | マイグレーション後も記録が参照できる |
| R3 | アンインストール後に再インストール | — | データは消える（想定どおり。バックアップ対象外） |

**補足（DT-OPS-002）**

- ※1（R2）: Phase 1 以降で DB バージョンを上げたリリース時に実施。失敗時は起動不能または空 DB となり得るため、更新前に実機で退避テストを推奨。
