## アーキテクチャ概要

オフライン完結のモバイルアプリとして、UI・ユースケース・ドメイン・データアクセス・DB を分離する。

```
+---------------------------------------------------------+
|              スマートフォン端末 (iOS / Android)           |
|  +----------------------------------------------------+ |
|  |  presentation/   入力・カレンダー・レポート・設定   | |
|  |       ▲▼                                           | |
|  |  application/    記録 CRUD・履歴取得・タイマー制御  | |
|  |       ▲▼                                           | |
|  |  domain/         エンティティ・リポジトリ IF        | |
|  |                  計算純粋関数 (Phase 2: 1RM)       | |
|  |       ▲▼                                           | |
|  |  data/           DAO・マイグレーション              | |
|  +--------▲▼------------------------------------------+ |
|           ▼                                              |
|  +----------------------------------------------------+ |
|  |  SQLite (app.db) — menu_master, training_logs        | |
|  +----------------------------------------------------+ |
+---------------------------------------------------------+
```

### レイヤ責務

| レイヤ | 責務 | MVP で実装 |
|---|---|---|
| presentation | タップ操作の受付、リスト・カレンダー表示、ダークテーマ適用 | ○ |
| application | ユースケースの編成、バリデーション、リポジトリ呼び出し | ○ |
| domain | エンティティ、リポジトリ抽象、将来の計算関数 | ○（計算は Phase 2） |
| data | SQL 生成、CRUD、スキーママイグレーション | ○ |
| core | テーマ、ルーティング、共通例外 | ○ |

## データモデル

マスタ（種目定義）とログ（セット履歴）を分離する。MVP では `users`・`daily_profiles` は未使用。

### ER（概念）

```
menu_master (1) ----< (N) training_logs
```

### テーブル定義

#### menu_master（種目マスタ）

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| menu_id | INTEGER | PK, AUTOINCREMENT | 種目 ID |
| name | TEXT | NOT NULL | 種目名（例: ベンチプレス） |
| category | TEXT | | 自重 / マシン / フリーウェイト等 |
| body_part | TEXT | | 胸・背中・脚・肩等 |
| calc_type | TEXT | | 将来の 1RM 計算区分（MVP では未使用可） |

#### training_logs（トレーニング記録）

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| log_id | INTEGER | PK, AUTOINCREMENT | ログ ID |
| menu_id | INTEGER | FK → menu_master | 種目 |
| trained_on | TEXT | NOT NULL | トレ日（YYYY-MM-DD）。**今日以前のみ**（未来日は不可） |
| weight_kg | REAL | NOT NULL | 重量（kg）。**小数第 2 位まで**（例: 82.50）。0 より大、上限 999.99 |
| reps | INTEGER | NOT NULL | 成功回数 |
| created_at | TEXT | NOT NULL | 登録日時（ISO 8601。並び順・同日複数セット用） |

#### users（将来・Could）

| カラム | 型 | 説明 |
|---|---|---|
| user_id | INTEGER PK | 仮名・身長・年齢・性別（1 レコード想定） |

#### daily_profiles（将来・Could）

| カラム | 型 | 説明 |
|---|---|---|
| date | TEXT PK | 記録日 |
| weight_kg | REAL | 体重 |
| calories | REAL | 摂取カロリー（メモ扱い） |

## 画面・ルーティング

### ナビゲーション構造

底部タブを主軸とし、タイマーはオーバーレイとする。**設定は底部タブ**とし、参照頻度の低い項目をまとめる（利用者承認 2026-08-18）。

```
[底部タブ]（4 つ）
  ├── 入力（トレーニング）
  │     ├── 日付・種目選択・重量・回数・保存
  │     ├── 当日・選択種目のセット一覧（各行にゴミ箱アイコン → 削除）
  │     └── 右上: タイマーアイコン → インターバルタイマー
  ├── カレンダー
  │     ├── 月表示（記録日は **記録マーク** のみ。MVP は数値なし）
  │     └── 日付ダブルタップ → 入力（該当日）
  ├── レポート
  │     └── MVP: プレースホルダ（「データ不足」等）可
  └── 設定
        ├── トレーニング履歴 → 履歴一覧（FR-HIS-001）
        ├── プライバシーポリシー（静的表示）
        └── アプリについて（バージョン）

[設定タブから遷移]
  └── 履歴一覧（FR-HIS-001）
        ├── 種目選択 → 日付降順リスト（各行ゴミ箱 → 削除）
        └── 戻る → 設定
```

**廃止（MVP）**: 入力画面右上の三点リーダ → 設定（設定タブに統合）。

### 画面一覧

| 画面 | 役割 | 関連 FR |
|---|---|---|
| 入力（トレーニング） | セット登録の主画面 | FR-REC-001,002,003 |

## コアロジック

### Phase 2: 1RM 算出（FR-CAL-001）

Epley 法を純粋関数として `domain/calculations/` に配置する。

```
1RM = weight_kg × (1 + reps / 30)
```

- UI 層・DB 層に依存しない
- 単体テストで境界値（1 回、高レップ）を検証する

### 将来参考: 目標値提示（FR-CAL-002・実装しない）

企画書のアルゴリズムを ADR またはコメントで保持するのみ。

| 条件 | 目標 |
|---|---|
| 前回レップ ≤ 10 | 前回重量 ×（前回レップ + 1）回を目安 |
| 前回レップ ≥ 11 | 前回重量 + 2.5kg × 8 回を目安 |

MVP では入力画面にこれらの目標値を **表示しない**。

### カレンダー集計（MVP）

該当日に `training_logs` が 1 件以上あれば、日付セルに **記録マーク** を表示する。記録が無い日はマークなし。**重量数値は表示しない**（利用者承認 2026-08-18）。

**将来構想**: 種目・部位ごとの最大重量をカレンダーに出す場合は **設定画面** で表示対象を選べるようにする（MVP 外。TEST-GAP-012 関連）。

Phase 2 以降、日付枠に 1RM を表示できる。

## データフロー（記録保存）

1. **presentation**: 重量・回数・種目・日付を入力し保存イベントを発火
2. **application**: バリデーション（種目 → 重量 → 回数の順で検証し、**最初の 1 件のエラーのみ** 返す。重量 > 0・小数第 2 位まで・回数 ≥ 1・**トレ日は今日以前** 等）
3. **data**: `INSERT INTO training_logs` を実行（`created_at` を付与）
4. **presentation**: 履歴・カレンダー用の状態を更新

タイマーは保存イベントと **連動しない**（自動起動しない・**カウント中も停止しない**。FR-SYS-002）。

---

## CSV 出力フロー（Phase 3・FR-SYS-001）

1. data 層が `training_logs` と `menu_master` を JOIN 取得
2. application 層で CSV 文字列に成形
3. OS 共有機能で端末ストレージへ保存

## セキュリティ・運用（設計レベル）

- 秘密情報・`.env` は不要（サーバー連携なし）
- DB ファイルはアプリサンドボックス内のみ（NFR-SEC-001）
- 機内モードでも SQLite アクセスのみで完結（NFR-OPS-001）
- 起動時間は cold start で実機計測（NFR-PERF-001）

### タイマー状態（MVP）

| 項目 | 挙動 |
|---|---|
| クイックスタート初回 | 90 秒 |
| 同一セッション内の次回 | 前回設定秒数を反映 |
| プロセス終了後 | 90 秒に戻る（永続化しない） |
| 記録保存時 | カウント中でも停止しない |
| 0 秒到達時 | **画面表示**（完了状態）＋**バイブ**。音は出さない（利用者承認 2026-08-18） |
| バックグラウンド | **終了予定時刻（`ends_at`）** を保持し、復帰時に残り秒を再計算（利用者承認 2026-08-18） |

**将来構想**: 設定画面でデフォルト秒数を変更可能（MVP 外）。

### 種目プリセット（MVP シード）

初回起動時に `menu_master` へ投入する 8 種目（利用者承認 2026-08-18）:

| # | 種目名 | 備考 |
|---|---|---|
| 1 | ベンチプレス | |
| 2 | バーベルスクワット | |
| 3 | デッドリフト | |
| 4 | ラットプルダウン | |
| 5 | レッグプレス | |
| 6 | 懸垂（重量＝体重＋重り） | 重量欄は **有効負荷 kg**（自重＋追加重量の合計）を手入力。アプリは体重を自動計算しない |
| 7 | 腕立て伏せ | |
| 8 | ショルダープレス | |

### 削除 UI（MVP）

セット一覧の各行に **ゴミ箱アイコン** を表示。タップ → 確認ダイアログ → 削除（FR-REC-003）。対象: 入力画面の当日一覧、履歴一覧。

技術選定の理由は [doc/adr/](../adr/) に ADR で残す（Flutter / SQLite 選定 ADR は Phase 1 着手時に追加）。
