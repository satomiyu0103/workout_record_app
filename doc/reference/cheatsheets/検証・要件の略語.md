# 検証・要件の略語（早見表）

最終更新: 2026-08-18

> 正本の利用: [08_検証設計.md](../../specs/08_検証設計.md) · [02_要件定義.md](../../specs/02_要件定義.md) · [04_機能一覧.md](../../specs/04_機能一覧.md)  
> 本プロジェクトの doc では、**略語を使うときは初出または同じ節の近くに日本語の正式名称を併記**する。

---

## 検証・品質

| 略語 | 正式名称 | 意味（平易に） |
| --- | --- | --- |
| **AC** | 受け入れ基準（Acceptance Criteria） | 「これができたら OK」と決めたチェック項目 |
| **DT** | デシジョンテーブル（Decision Table） | 条件の組み合わせごとに、何が起きるべきかを書いた表 |
| **ST** | 状態遷移表（State Transition） | アプリや環境が「どの状態からどの状態へ変わるか」の表 |
| **QA** | 品質保証（Quality Assurance） | リリース前に仕様どおりか確認する作業全体 |
| **MVP** | 最小限の製品（Minimum Viable Product） | 最初に使える形で出す版（本アプリでは Phase 1） |
| **R**（表の行） | ルール | デシジョンテーブルの 1 行＝テスト候補 1 件 |

---

## 要件コード

| 略語 | 正式名称 | 意味（平易に） |
| --- | --- | --- |
| **FR** | 機能要件（Functional Requirement） | アプリが「何ができるか」の要件。`FR-○○-001` の形式 |
| **NFR** | 非機能要件（Non-Functional Requirement） | 速度・オフライン・安全など「どう動くか」の要件 |

### 機能要件のカテゴリ（FR の真ん中の英字）

| 略語 | 正式名称 | このアプリでの内容 |
| --- | --- | --- |
| **EXR** | 種目マスタ（Exercise） | ベンチプレス等の種目の登録・選択 |
| **REC** | トレーニング記録（Record） | 重量×回数の保存・参照・削除 |
| **HIS** | 履歴・カレンダー（History） | 過去の記録の一覧・カレンダー表示 |
| **SYS** | システム機能（System） | タイマー・テーマ・CSV 等 |
| **CAL** | 計算（Calculate） | 1RM 算出など |
| **VIS** | 可視化（Visualization） | グラフ表示 |
| **NEG** | 否定検証（Negative） | 「表示してはいけない」ことの確認（コード上の分類） |
| **DPL** | 配布（Deploy） | APK ビルド・実機インストール |
| **OPS** | 運用（Operations） | 日常利用・更新後のデータ保持 |

---

## Android・開発環境

| 略語 | 正式名称 | 意味（平易に） |
| --- | --- | --- |
| **APK** | Android パッケージ | スマホに入れるインストール用ファイル |
| **API** | アプリケーションプログラミングインターフェース | ここでは **Android の OS バージョン番号**（例: API 26＝Android 8.0） |
| **SDK** | ソフトウェア開発キット | PC でアプリをビルドするために必要な部品一式 |
| **DB** | データベース | 記録を保存する仕組み（本アプリは SQLite） |

## 読み方の例

| 表記 | 読み方 |
| --- | --- |
| `FR-REC-001` | 機能要件・記録カテゴリ・001 番 |
| `DT-REC-003 R3` | デシジョンテーブル DT-REC-003 の **ルール 3 行目** |
| `AC-DPL` | 受け入れ基準のうち「配布」に関するもの |
| `ST-DPL-001` | 状態遷移表・配布パイプライン・001 番 |
| `PW-REC-01` | ペアワイズテスト・記録登録スイート・01 番（[08c](../../specs/08c_検証設計_組み合わせテスト.md)） |
| `OA-INT-01` | 直交法・画面横断スイート・01 番（[08c](../../specs/08c_検証設計_組み合わせテスト.md)） |
